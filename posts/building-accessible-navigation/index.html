Building Navigation That Works for Everyone

A practical guide to semantic, keyboard-friendly navigation for responsive websites.

Nnamdi Ileh3 July 20268 min read
  • Accessibility
  • HTML
  • JavaScript

Navigation is one of the most important interfaces on a website. When it fails, people cannot reliably discover the rest of your work. A good menu should work with a mouse, keyboard, touch screen, screen reader, and zoomed layout.

Start with semantic HTML

Use a real <nav> landmark and ordinary links. The browser already understands links, supports keyboard activation, and exposes their purpose to assistive technology.

<nav aria-label="Primary navigation">
    <a href="/" aria-current="page">Home</a>
    <a href="/posts/">All posts</a>
    <a href="/about/">About</a>
    <a href="/contact/">Contact</a>
</nav>

Avoid replacing links with clickable <div> elements. Doing so means rebuilding keyboard behaviour, focus styles, semantics, and browser features that links already provide.

Use a real button for the mobile menu

A menu toggle changes interface state, so it should be a <button>. Connect it to the controlled navigation with aria-controls, and expose its current state with aria-expanded.

<button
    type="button"
    aria-expanded="false"
    aria-controls="primary-navigation"
>
    Menu
</button>

Keep the accessibility state in sync

When JavaScript opens the menu visually, it must also update the accessible state.

const toggle = document.querySelector("[data-nav-toggle]");
const navigation = document.querySelector("[data-primary-nav]");

toggle.addEventListener("click", () => {
    const isOpen = toggle.getAttribute("aria-expanded") === "true";

    toggle.setAttribute("aria-expanded", String(!isOpen));
    navigation.classList.toggle("is-open", !isOpen);
});

Make focus visible

Keyboard users need to see which control currently has focus. Do not remove outlines unless you replace them with something equally visible.

:focus-visible {
    outline: 0.2rem solid #d9643a;
    outline-offset: 0.2rem;
}

Support Escape and responsive changes

Closing an open mobile menu with the Escape key is a helpful convention. You should also reset the menu state when the screen becomes wide enough to show desktop navigation.

Accessibility checklist

  • The navigation has a useful accessible name.
  • The menu toggle is a button.
  • aria-expanded reflects the visible state.
  • All links are reachable and visible with the keyboard.
  • Focus styles have sufficient contrast.
  • The current page uses aria-current="page".

Key takeaways

Accessible navigation does not require a large library. Start with the correct HTML elements, preserve native link behaviour, expose state changes, and test the complete interaction with only a keyboard.
